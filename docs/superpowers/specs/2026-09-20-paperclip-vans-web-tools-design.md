# Paperclip Vans Web Tools — дизайн

Дата: 2026-09-20  
Статус: одобренная концепция, перед планированием реализации

## 1. Цель

Создать отдельный доверенный плагин Paperclip, который даёт агентам контролируемый доступ к публичному интернету через два маршрута VansRouter:

- поиск: `POST /v1/search`;
- извлечение содержимого страницы: `POST /v1/web/fetch`.

Плагин не является браузером. Управление страницей, JavaScript-интерфейсы, формы, cookies, авторизованные сессии, скриншоты и действия пользователя будут реализованы отдельным плагином.

## 2. Граница первой версии

Плагин регистрирует два инструмента агента:

1. `vans_web_search` — поиск в интернете.
2. `vans_web_fetch` — извлечение текста публичной веб-страницы.

Первая версия не предоставляет:

- произвольные HTTP-методы или заголовки;
- доступ к произвольным API;
- загрузку и отправку файлов;
- выполнение JavaScript;
- нажатия, заполнение форм и браузерную навигацию;
- cookies и постоянные пользовательские сессии;
- прямой доступ к внутренним адресам и служебным сетям;
- API-ключ VansRouter агенту или в результатах инструмента.

## 3. Архитектура

```text
Агент Paperclip
    │
    ├── vans_web_search
    └── vans_web_fetch
             │
             ▼
  Плагин Paperclip @zaruba/paperclip-vans-web-tools
             │
             ├── проверка параметров
             ├── загрузка instance config
             ├── разрешение apiKeyRef через Paperclip secrets
             ├── ограничение времени и размера
             ├── фильтрация ответа
             └── безопасный клиент VansRouter
                    │
                    ▼
            VansRouter
              /v1/search
              /v1/web/fetch
```

Плагин является тонким адаптером. Он не дублирует поисковый движок, HTML-парсер или браузерный движок.

## 4. Манифест Paperclip

Предлагаемая идентичность:

- пакет: `@zaruba/paperclip-vans-web-tools`;
- идентификатор плагина: `zaruba.vans-web-tools`;
- отображаемое имя: `Vans Web Tools`;
- версия MVP: `0.1.0`.

Минимальные capabilities:

- `agent.tools.register`;
- `http.outbound`;
- `secrets.read-ref`;
- `instance.settings.register`.

Первая версия не содержит UI-кода. Форма настроек создаётся автоматически по `instanceConfigSchema`. Это исключает лишний UI-бандл и снижает объём кода.

Манифест экспортирует объект типа `PaperclipPluginManifestV1`:
- `id: "zaruba.vans-web-tools"`;
- `apiVersion: 1`;
- `version: "0.1.0"`;
- `displayName: "Vans Web Tools"`;
- `description: "Web search and page fetch via VansRouter"`;
- `categories: ["connector"]`;
- `entrypoints: { worker: "./dist/worker.js" }`;
- `tools`: два инструмента (`vans_web_search`, `vans_web_fetch`).
- `instanceConfigSchema`: схема параметров экземпляра.

## 4.1. Контракт SDK

Плагин опирается на официальный `@paperclipai/plugin-sdk`:
- инициализация: `definePlugin({ setup, onHealth, onValidateConfig })`;
- запуск воркера: `runWorker(plugin, import.meta.url)`;
- регистрация инструментов: `ctx.tools.register(name, declaration, async (params, runCtx) => ToolResult)`;
- результат инструмента `ToolResult`:
  - `content`: обязательная строка для агента;
  - `data`: структурированные метаданные;
  - `error`: строка ошибки при сбое;
- чтение секрета: `await ctx.secrets.resolve(secretRef)`.
- сетевой клиент: `ctx.http.fetch(...)` с таймаутом `AbortSignal.timeout(...)`; Paperclip проверяет capability `http.outbound` и сохраняет трассировку.


## 5. Конфигурация экземпляра

`instanceConfigSchema` использует `additionalProperties: false`.

Поля:

### `baseUrl`

- тип: string;
- обязательно;
- пример для общей Docker-сети: `http://vansrouter:20128`;
- пример для публичного маршрута: `https://rout.unicrawl.ru`;
- путь `/v1` в значении запрещён: плагин сам добавляет `/v1/search` и `/v1/web/fetch`;
- query и fragment запрещены;
- протокол: `http` или `https`;
- итоговый URL нормализуется без завершающего `/`.

`baseUrl` — доверенная операторская настройка. Ограничение SSRF для пользовательских URL не применяется к нему, поскольку локальный VansRouter может находиться в Docker-сети.

### `apiKeyRef`

- обязательно;
- хранится как ссылка на секрет Paperclip;
- значение ключа разрешается только во время вызова инструмента через `ctx.secrets.resolve`;
- значение не сохраняется в состоянии плагина и не пишется в журнал.

### `searchProvider`

- тип: string;
- значение по умолчанию: `searxng`;
- в MVP принимает только `searxng`.

### `fetchProvider`

- enum: `scrapling`, `jina-reader`, `camofox`;
- значение по умолчанию: `scrapling`;
- выбирается оператором, а не агентом.

Режим `auto` в MVP не включается: живой VansRouter не предоставляет отдельного универсального провайдера `default`, а скрытая цепочка отката усложнит диагностику. Оператор выбирает один рабочий источник явно.

### `timeoutMs`

- integer;
- значение по умолчанию: `30000`;
- минимум: `1000`;
- максимум: `60000`.

### `maxSearchResults`

- integer;
- значение по умолчанию: `5`;
- минимум: `1`;
- максимум: `20`.

### `maxContentChars`

- integer;
- значение по умолчанию: `20000`;
- минимум: `1000`;
- максимум: `100000`.

### `allowedDomains`

- массив доменных имён;
- по умолчанию пустой — разрешены все публичные домены;
- если массив непустой, допускается точное доменное имя и его поддомены;
- IP-адреса в этом списке запрещены.

### `blockedDomains`

- массив доменных имён;
- по умолчанию пустой;
- применяется после `allowedDomains` и имеет приоритет;
- блокирует точное доменное имя и его поддомены.

## 6. Проверка конфигурации

`onValidateConfig` проверяет:

- точный набор полей;
- корректность `baseUrl`;
- обязательное наличие `apiKeyRef`;
- допустимые enum и числовые границы;
- канонический вид доменных имён;
- отсутствие пересечений, которые делают настройки заведомо бессмысленными;
- доступность `GET <baseUrl>/api/health` при команде проверки подключения;
- реальный тест авторизации через ограниченный запрос VansRouter, когда Paperclip передаёт секретный контекст.

Проверка подключения не должна печатать ключ или полный заголовок Authorization.

## 7. Инструмент `vans_web_search`

### Вход

```json
{
  "query": "строка",
  "maxResults": 5,
  "searchType": "web",
  "language": "ru",
  "country": "RU",
  "timeRange": "month"
}
```

Поля:

- `query`: обязательная непустая строка, не более 500 символов;
- `maxResults`: необязательно, 1–20, дополнительно ограничивается настройкой `maxSearchResults`;
- `searchType`: `web` или `news`, по умолчанию `web`;
- `language`: необязательный короткий код языка;
- `country`: необязательный двухбуквенный код страны;
- `timeRange`: необязательно, `day`, `week`, `month`, `year`.

Неизвестные поля запрещаются.

### Запрос VansRouter

```json
{
  "model": "searxng",
  "query": "...",
  "max_results": 5,
  "search_type": "web",
  "language": "ru",
  "country": "RU",
  "time_range": "month"
}
```

### Выход

Нормализованный результат:

```json
{
  "provider": "searxng",
  "query": "...",
  "results": [
    {
      "title": "...",
      "url": "https://...",
      "snippet": "...",
      "publishedAt": null,
      "position": 1,
      "sourceType": "bing"
    }
  ],
  "truncated": false
}
```

Ограничения:

- не более эффективного `maxResults`;
- `title` не более 300 символов;
- `snippet` не более 2000 символов;
- сохраняются только известные безопасные поля;
- `provider_raw` и другие произвольные данные провайдера агенту не передаются;
- URL результата проходят базовую проверку `http(s)` перед возвратом.

## 8. Инструмент `vans_web_fetch`

### Вход

```json
{
  "url": "https://example.com/article",
  "format": "markdown",
  "maxChars": 20000
}
```

Поля:

- `url`: обязательный абсолютный URL `http` или `https`;
- `format`: `markdown` или `text`, по умолчанию `markdown`;
- `maxChars`: необязательно, 1000–100000, дополнительно ограничивается `maxContentChars`.

Провайдер не передаётся агентом; используется операторская настройка `fetchProvider`.

Неизвестные поля запрещаются.

### Запрос VansRouter

```json
{
  "provider": "scrapling",
  "url": "https://example.com/article",
  "format": "markdown"
}
```

### Выход

```json
{
  "provider": "scrapling",
  "url": "https://example.com/",
  "title": "Example Domain",
  "format": "markdown",
  "content": "...",
  "contentChars": 165,
  "truncated": false
}
```

Ограничения:

- текст обрезается по Unicode-символам до эффективного `maxChars`;
- бинарное содержимое не возвращается;
- произвольные данные провайдера не возвращаются;
- ключ и внутренние заголовки никогда не попадают в результат;
- ответ содержит признак `truncated`.

## 9. Сетевая безопасность

### Проверка пользовательского URL

До обращения к VansRouter плагин:

1. принимает только `http:` и `https:`;
2. запрещает username/password в URL;
3. запрещает fragment;
4. приводит hostname к нижнему регистру;
5. запрещает `localhost`, `.localhost`, `.local`, `.internal`, `.home.arpa`;
6. запрещает прямые IP из loopback, private, link-local, multicast, unspecified, CGNAT и документационных диапазонов;
7. разрешает только порты `80` и `443` либо отсутствие явного порта;
8. применяет `allowedDomains` и `blockedDomains`.

### DNS rebinding

Поскольку фактическое скачивание выполняет VansRouter, сам плагин не может надёжно проверить конечный адрес после DNS и перенаправлений. Поэтому защита должна быть двухслойной:

- плагин отбрасывает очевидно опасные URL до отправки;
- VansRouter/web-fetch provider обязан повторно применять сетевую политику к каждому разрешённому адресу и перенаправлению.

Критерий установки в production: живой VansRouter должен быть проверен отрицательными тестами на loopback, RFC1918, link-local и metadata endpoint. Если провайдер позволяет получить внутренний адрес через DNS или redirect, плагин не устанавливается до исправления VansRouter.

## 10. HTTP-клиент VansRouter

Один внутренний клиент обслуживает оба инструмента.

Правила:

- используется встроенный `fetch` Node.js;
- заголовок `Authorization: Bearer <secret>` создаётся внутри клиента;
- `Content-Type: application/json`;
- `AbortSignal.timeout` или `AbortController` ограничивает время;
- тело ответа читается с жёстким лимитом байтов до полного JSON-разбора;
- non-2xx преобразуется в безопасную ошибку;
- сообщения ошибок очищаются от URL с credentials, ключей и заголовков;
- автоматических повторов в MVP нет;
- `429` возвращает понятный признак ограничения и безопасный `retryAfter`, если он есть;
- `401/403` возвращает операторскую ошибку конфигурации, не раскрывая ключ;
- `5xx` возвращает временную ошибку VansRouter.

## 11. Модель ошибок

Инструмент возвращает короткий машиночитаемый код и русское безопасное сообщение:

- `invalid_input`;
- `url_not_allowed`;
- `configuration_error`;
- `authentication_failed`;
- `rate_limited`;
- `upstream_timeout`;
- `upstream_unavailable`;
- `response_too_large`;
- `invalid_upstream_response`.

Агенту не возвращаются stack trace, тело неизвестной upstream-ошибки, секретные ссылки или внутренние пути.

## 12. Журналирование

Разрешено журналировать:

- имя инструмента;
- длительность;
- код результата;
- количество результатов;
- длину извлечённого содержимого;
- hostname без query и fragment.

Запрещено журналировать:

- API-ключ;
- заголовок Authorization;
- полное содержимое страницы;
- полный поисковый ответ;
- URL с query, если он может содержать токены;
- значение секрета или его расшифрованное представление.

## 13. Тестирование

### Модульные тесты

- нормализация конфигурации;
- неверный `baseUrl`;
- отсутствие `apiKeyRef`;
- допустимые границы чисел;
- точная проверка входных полей;
- нормализация результата поиска;
- обрезка строк;
- нормализация результата извлечения;
- безопасное преобразование upstream-ошибок;
- отсутствие секретов в ошибках и журналах;
- проверка доменных списков;
- запрет внутренних адресов и опасных схем.

### Интеграционные тесты с поддельным VansRouter

Локальный HTTP-сервер стандартной библиотеки Node.js проверяет:

- правильные пути `/v1/search` и `/v1/web/fetch`;
- корректный Bearer-заголовок;
- правильное тело запроса;
- обработку `200`, `400`, `401`, `403`, `429`, `500`, timeout;
- слишком большой ответ;
- невалидный JSON;
- отсутствие передачи ключа в результат.

### Живые проверки до установки

Из среды, где будет работать worker плагина:

1. `/api/health` VansRouter отвечает успешно;
2. поиск `example domain` возвращает хотя бы один `http(s)` результат;
3. извлечение `https://example.com` выбранным provider возвращает непустой текст;
4. запросы к loopback/private/link-local/metadata блокируются;
5. значение ключа не встречается в журнале теста.

### Проверка Paperclip после установки

- плагин имеет статус `ready`;
- health плагина `ok`;
- зарегистрировано ровно два инструмента;
- тестовый агент видит оба namespaced-инструмента;
- тестовый запуск выполняет поиск;
- тестовый запуск получает содержимое `https://example.com`;
- агент не видит API-ключ;
- обычный агент не получает произвольный HTTP-инструмент.

## 14. Развёртывание и откат

Разработка ведётся в отдельном репозитории. Production не изменяется до отдельного подтверждения.

Предпочтительный способ установки:

1. собрать и проверить пакет;
2. скопировать готовый каталог в постоянный volume Paperclip, например `/paperclip/plugins-local/paperclip-vans-web-tools`;
3. установить через официальный `POST /api/plugins/install` с краткоживущим board key;
4. задать instance config;
5. создать/выбрать encrypted secret и сохранить только `apiKeyRef`;
6. активировать плагин;
7. выполнить проверку одним тестовым агентом;
8. только после проверки предоставить инструменты целевым агентам.

Откат:

- отключить плагин штатным API;
- убедиться, что инструменты исчезли из каталога;
- при необходимости удалить пакет штатным API;
- секрет VansRouter не удалять автоматически, поскольку он может использоваться другими интеграциями.

## 15. Критерии приёмки MVP

MVP принят, когда подтверждено инструментами:

1. Сборка, typecheck и тесты проходят.
2. Манифест объявляет только необходимые capabilities.
3. В настройках отсутствует поле с открытым API-ключом; используется `apiKeyRef`.
4. `vans_web_search` возвращает нормализованные ограниченные результаты живого поиска.
5. `vans_web_fetch` возвращает ограниченный markdown/text живой страницы.
6. Опасные URL блокируются до обращения к VansRouter.
7. Негативные сетевые тесты подтверждают, что VansRouter не извлекает внутренние адреса.
8. Секрет отсутствует в результатах, ошибках и журналах.
9. Paperclip показывает ровно два инструмента тестовому агенту.
10. Полноценный браузер и произвольный HTTP отсутствуют.

## 16. Отложенный объём

Отдельный браузерный плагин будет спроектирован после этого MVP. В него могут войти:

- открытие JavaScript-страниц;
- скриншоты;
- переходы и клики;
- заполнение форм;
- авторизованные и постоянные сессии;
- Browserless/Camofox;
- файлы, загрузки и визуальная проверка.

Этот объём не добавляется в `paperclip-vans-web-tools`.
